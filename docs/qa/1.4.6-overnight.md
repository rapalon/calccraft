## 4. Code review of the lifecycle fix (no device needed)

I read the code paths that a device run would exercise, on 1.4.6 (`a6cb8c0`), looking for crashes
that the Pixel runs of 3ec17022 couldn't show (older Android versions, other form factors):

- **Destroy hook** (`src/lib.rs` `calccraft_on_create`, `end_on_destroy`): android-activity's
  `ANativeActivity_onCreate` runs first, then `onDestroy` is replaced by a `_exit(0)`. A destroy
  that can't be avoided (an overlay change, Don't keep activities, a recents swipe that finishes
  the task) ends the process instead of blocking the main thread. So no ANR, and no crash dialog:
  Android records `EXIT_SELF`/"app died, no saved state", not `CRASH`. The state is saved before,
  on `Suspended`.
- **Manifest** (`android/AndroidManifest.xml`): `configChanges` names all 18 values, so rotation,
  multi-window and split-screen resizes, font scale, display size (`density`), dark/light
  (`uiMode`), locale and Bold text (`fontWeightAdjustment`, API 31+) are handled without a
  relaunch. On API 24–30 the newer flags (`fontWeightAdjustment`, `grammaticalGender`) are bits
  that the platform ignores. They are not attributes it rejects: aapt2 compiles the names against
  android-36. `singleTask` sends `am start -n` and launcher intents to the running activity.
- **Back button**: on the first screen it calls `moveTaskToBack` (`src/app/android.rs`), not
  `finish`, so back doesn't destroy the activity. With Don't keep activities on, the later destroy
  goes through the hook above.
- **Panics**: there is no `panic = "abort"` profile, so `catch_unwind` in `android_main` catches
  a panic. The process then ends with exit code 1 after logging it (tag `CalcCraft`). A Rust panic
  would show as `EXIT_SELF` with a logged message, not as Android's crash dialog.
- **JNI on old Android versions** (`src/app/android.rs`): every call that is newer than
  minSdk 24 is gated by `Build.VERSION.SDK_INT`:
  - `VibratorManager` (31)
  - `hasAmplitudeControl` / `VibrationEffect` (26)
  - `areAllPrimitivesSupported` (30)
  - `getResonantFrequency` / `getPrimitiveDurations` (31)
  - `createPredefined` (29, `vibration::tap`)
  - `WindowInsets.Type` / `getInsets` / `isVisible` (30)

  A failed call returns `Err`, and `with_activity` clears the pending Java exception after the
  local frame is popped. `PopLocalFrame` is one of the JNI calls that are allowed with an exception
  pending. So a missing method logs once and doesn't crash. The vendored AccessKit adapter skips
  the tree below API 26 instead of panicking.
- **Not reviewable without a device**: GL surface loss and recreation on emulator GPUs
  (SwiftShader / host GPU), large-screen behaviour (Android 16 ignores the orientation request
  there, `orientation::honored`), and whatever Google's crawler did to get the "Clear cache"
  dialog. That dialog appears only after repeated crashes or ANRs. 3ec17022 explains it by the two
  fixed findings, but it was never reproduced exactly.

**Compared with 1.4.5:** both 1.4.5 failures (a second activity ends the process; a relaunch
freezes it) have direct guards in 1.4.6, and both were verified on the Pixel by 3ec17022. This
review found no third path to a crash or ANR. That is not the same as a device run.

## 5. The re-run, once adb and the emulator are allowed

Build (release config, the same commands as `release.yml` with a test applicationId, no R8: there
is none, see `docs/play-rejection-1.4.5.md`):

```
pwsh -File android/build-apk.ps1 -ApplicationId com.rapalon.calccraft.rc146 -Channel play-free -PaidApplicationId com.rapalon.calccraft.pro
pwsh -File android/build-apk.ps1 -ApplicationId com.rapalon.calccraft.pro.rc146 -Channel play-paid -PaidApplicationId com.rapalon.calccraft.pro
```

`build-apk.ps1` builds only `arm64-v8a` (`cargo ndk -t arm64-v8a`, `lib/arm64-v8a`). The x86_64
emulators need either an ABI parameter in the script or arm64 system images. Arm64 images on an
x86_64 host can't boot API 30+ with Google APIs, so the script needs the parameter. Because the
build was refused, this run couldn't build or test such a change, and I didn't change the
release script blind.

Pixel check (rc146 only; never touch `com.rapalon.calccraft`, `.pro`, `.test`, `.pro.test`,
`.a11ytest`, `.lifecycle`):

1. `adb -s 28171FDH30091W install -r target/android/CalcCraft-Play-1.4.6-arm64.apk`, start it,
   note the pid (`pidof com.rapalon.calccraft.rc146`).
2. `pwsh -File tests/device/run.ps1 -Serial 28171FDH30091W -Package com.rapalon.calccraft.rc146 -Out target/device-results.md`
3. Bold text: `settings put secure font_weight_adjustment 300`, tap a key: same pid, no ANR. Then
   `settings delete secure font_weight_adjustment`.
4. `settings put system font_scale 1.3`, then `2.0`, then back to the old value. Then
   `wm density` (a larger display size), then `wm density reset`. `cmd uimode night yes/no`, a
   locale change, rotation, split screen. Same pid and keys working after each.
5. Don't keep activities (`settings put global always_finish_activities 1`): home, then relaunch.
   Expect a clean `EXIT_SELF` and a restart with the state restored. Then set it back to 0.
6. `am start -n com.rapalon.calccraft.rc146/android.app.NativeActivity` while running: same pid.
7. `am kill` in the background, then relaunch. Back and home with the history and memory flyouts
   and the menu open.
8. `monkey -p com.rapalon.calccraft.rc146 -s <seed> --throttle 30 --pct-syskeys 2 --pct-appswitch 1 --pct-rotation 3 -v 5000`
   for seeds 1–10 (3–6 hit 1.4.5's findings).
9. Per run: `logcat -b crash,main,system` filtered for `AndroidRuntime|FATAL|ANR|Fatal signal|CalcCraft`,
   `/data/tombstones` (via `dumpsys dropbox --print` on a user build), and
   `dumpsys activity exit-info com.rapalon.calccraft.rc146`.
10. Restore every setting changed in steps 3–5.

The emulators get the same steps, with `cmd overlay` / `cmd theme` for the wallpaper colours on
API 31+. The tablet and the foldable add `wm size` changes and a fold posture change.
