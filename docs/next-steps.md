## Краткое резюме (Executive Summary)

Проект **CalcCraft** находится в исключительно зрелом инженерном состоянии. Ключевые математические и интерфейсные компоненты Windows 11 Calculator уже реализованы на Rust с использованием `eframe`/`egui`:
- **Математическое ядро:** Полная точная арифметика на рациональных дробях (`BigRational`), 32/40-значные вычисления для функций Scientific-режима, побитовая арифметика Programmer-режима и автономный 2D-графопостроитель с символьно-числовым анализом функций. Пройдено **296 модульных тестов** (включая golden-тесты Microsoft Calculator и property/fuzz-тесты `src/monkey.rs`).
- **Кроссплатформенность:** Десктопная сборка (Windows, Linux, macOS), работающая веб-версия (WASM + PWA с офлайн-сервис-воркером через Trunk и деплоем на GitHub Pages), прототип под Android (NativeActivity + OpenGL ES).
- **Юридическая и графическая чистота:** Иконка приложения полностью сгенерирована процедурно в коде (`src/icon.rs`) и **не заимствует защищенные графические ассеты Microsoft**. Иконки меню взяты из открытого MIT-набора Fluent System Icons, шрифты — Inter и Noto Sans Math (SIL OFL).

**Ключевые проблемы и точки внимания, требующие решения прямо сейчас:**
1. **Ребрендинг и битые ссылки:** Проект был передан организации Rapalon Labs (`rapalon/calccraft`), однако в `README.md`, коде приложения (`src/app.rs`), манифестах Android и воркфлоу GitHub Actions все внешние ссылки, бейджи, страницы деплоя и Bundle ID до сих пор указывают на старый репозиторий `gavrilov/calccraft`.
2. **Неточности в README и позиционировании:** В документации указано «50 языков», хотя фактически переведено **60 языков**; присутствует дублирующийся дисклеймер; десктопное позиционирование принижает Linux и macOS («Windows is the platform CalcCraft is made for»).
3. **Риск зависания релизов в статусе черновика (Draft):** Скрипт `release.yml` создает draft-релиз и публикует его только при 100% успехе всех пяти сборок (Windows, Linux, 2x macOS, Android). Сбой в любой из них (например, отсутствие секретов подписи Android) блокирует публикацию релиза навсегда.
4. **macOS-сборки:** Создаются два раздельных `.zip` архива (Intel и ARM64) вместо единого Universal 2 бинарника (`lipo`), что создает путаницу для пользователей Mac.
5. **Дилемма Android:** Текущий NativeActivity-прототип ограничен (нет буфера обмена, шаринга, доступности TalkBack, нет Gradle/AAB для Google Play). Переход на **PWA/TWA (Trusted Web Activity)** позволит получить полноценное приложение в Google Play в разы быстрее и без накопления технического долга.

### 7. Стратегия для Android: переход на PWA/TWA (Trusted Web Activity) `[DECISION]`
- **Почему это важно:** Исследование в `docs/mobile-apps-research.md` и анализ текущего прототипа в `android/` показывают, что путь нативного Rust-приложения (`NativeActivity`) на мобильных ОС сопряжен с колоссальным объемом рутинной работы:
  - Нет буфера обмена (arboard не собирается под Android, нужен ручной JNI-мост с `ClipboardManager`).
  - Нет нормального шеринга.
  - Нет поддержки чтения с экрана (TalkBack требует миграции на `GameActivity`).
  - Нет сборки Android App Bundle (AAB), обязательной для Google Play с 2021 года.
  - Скрипт сборки `build-apk.ps1` написан вручную в обход стандартного Gradle.
  В то же время веб-версия (WASM) уже полностью адаптирована под мобильные экраны, поддерживает тач-зум графика, сохраняет состояние в LocalStorage и работает офлайн.
- **Решение:**
  - Создать проект **TWA (Trusted Web Activity)** с помощью Google Bubblewrap или минимального Android Studio / Gradle проекта, оборачивающего PWA.
  - Это сразу дает: работающий буфер обмена, нативный шеринг, правильное поведение экранной клавиатуры, поддержку Google Play (AAB), автоматическое получение обновлений через веб без необходимости перевыпускать APK.
  - Нативный `NativeActivity` оставить как экспериментальный прототип для узких энтузиастов или перевести на `android-game-activity` в отдаленной перспективе.
- **Трудоемкость:** **S** для TWA; **L** при сохранении нативного пути.
- **Зависимости:** Решение владельца; развернутая на GitHub Pages веб-версия (Шаг 1).
- **Исполнитель:** AI-агент готовит проект TWA и CI-сборку AAB; Владелец регистрирует Google Play Console ($25) и проводит 14-дневное тестирование.

### 8. Интеграция математического ядра CalcCraft в виде MCP-сервера `[READY]`
- **Почему это важно:** В коммите `550be78f` упоминалась ветка с наработками MCP. Математический движок CalcCraft (`engine.rs`, `math.rs`, `integer.rs`, `graphing`, `converter.rs`) полностью отвязан от UI и является уникальным активом: точная рациональная арифметика произвольной точности, 32-значные тригонометрические функции, побитовая математика и надежный анализ графиков.
  Большие языковые модели (LLM) систематически ошибаются в сложной арифметике и конверсиях. Предоставление CalcCraft в виде сервера Model Context Protocol (MCP) превратит его в инструмент для Claude Desktop, Cursor и других агентских сред.
- **Что сделать:**
  - Добавить бинарный таргет или отдельный флаг: `calccraft-mcp` (или запуск `calculator --mcp`).
  - Экспортировать MCP-инструменты:
    - `calculate(expression, mode)` — вычисление выражений со строгой гарантией точности (Standard, Scientific, Programmer);
    - `convert_units(value, from_unit, to_unit, category)` — конвертация величин;
    - `analyze_function(equation, x_min, x_max)` — точный анализ функции (нули, экстремумы, асимптоты, период);
    - `date_difference(from_date, to_date)` / `date_add_sub(...)` — точный расчет интервалов дат.
  - Подготовить документацию и конфигурацию подключения для Claude Desktop и Cursor.

### 12. Расширенные математические режимы нового поколения `[READY]`
- **Почему это важно:** Windows 11 Calculator — отличный стандарт, но он ограничен парадигмой классического кнопочного калькулятора. Внедрение инновационных режимов позволит CalcCraft превзойти оригинал и стать любимым инструментом ученых, инженеров и разработчиков.
- **Потенциальные направления (по приоритету):**
  1. **Режим свободных выражений (Free-form / Command-line Math):** Однострочное поле ввода (а-ля Alfred, Spotlight, SpeedCrunch), где можно печатать формулу целиком с клавиатуры (`(12 + 5) * 3 / 2` или `sin(45 deg) + 2^8`) с моментальным отображением результата без кликов по кнопкам.
  2. **Режим блокнота вычислений (Notepad / Scratchpad):** Многострочный документ в стиле Soulver / Numi / Calca, где каждая строка вычисляется, поддерживаются переменные (`цена_товара = 150`, `доставка = 20`, `итого = цена_товара * 3 + доставка`).
  3. **Вычисления с размерностями (Units in calculation):** Прямые вычисления с физическими величинами (`5 km + 300 m = 5.3 km`, `100 W * 2 h = 0.2 kWh`).
  4. **Комплексные числа и матрицы:** Поддержка алгебраической и тригонометрической формы комплексных чисел, матричные операции (определители, умножение, обращение).
- **Трудоемкость:** **L**
- **Зависимости:** Нет (движок расширяем).
- **Исполнитель:** AI-агент выполняет поэтапно (проектирование спецификации -> ядро -> UI).

### 13. Официальные магазины приложений: Microsoft Store, Google Play, Apple App Store `[BLOCKED/DECISION]`
- **Почему это важно:** Присутствие в официальных магазинах платформы снимает любые предупреждения SmartScreen / Gatekeeper о неизвестном издателе и дает максимальный охват массовой аудитории.
- **Особенности и риски платформ:**
  - **Microsoft Store:** Наиболее органичен. Требует упаковки в MSIX (через `msix-packaging` или Microsoft Store Developer CLI) и бесплатного/недорогого аккаунта Windows Partner Center.
  - **Google Play:** Требует разовой оплаты $25, прохождения закрытого тестирования (12 тестеров в течение 14 дней для новых личных аккаунтов). Рекомендуется реализовывать через TWA (Шаг 7).
  - **Apple App Store (macOS & iOS):** Требует ежегодной подписки $99/год в Apple Developer Program. **Высокий риск отклонения модерацией Apple** по правилам Guideline 4.1 (Copycats) из-за внешнего сходства с калькулятором конкурирующей ОС Windows. Для macOS гораздо безопаснее использовать распространение вне Store (с нотаризацией или через Homebrew).
- **Трудоемкость:** **M** на подготовку; время ожидания модерации.
- **Зависимости:** Решение и финансовые затраты владельца (аккаунты, сертификаты подписи).
- **Исполнитель:** Совместно (агент готовит сборки и манифесты, владелец оплачивает аккаунты и отправляет на ревью).

## Открытые вопросы для владельца (Open Questions)

1. **Android: PWA/TWA или нативный NativeActivity/GameActivity?**
   - *Рекомендация:* Использовать **TWA (Trusted Web Activity)**. Веб-версия CalcCraft на WASM уже превосходно оптимизирована под мобильные экраны, поддерживает офлайн-режим (PWA) и сенсорные жесты. TWA позволяет получить полноценный рабочий AAB-пакет для Google Play с поддержкой буфера обмена, шаринга и автообновлений буквально за 1–2 дня работы агента. Развитие нативного Rust-варианта потребует недель работы над низкоуровневыми JNI-мостами и сборкой.
2. **Проверка текущего релиза v1.3.2 на GitHub:**
   - Не заблокирован ли текущий релиз v1.3.2 в статусе черновика (`Draft`) на `https://github.com/rapalon/calccraft/releases` из-за возможного сбоя джобы `publish` в CI? Требуется визуальная проверка владельцем в веб-интерфейсе GitHub.
3. **Регистрация в магазинах приложений:**
   - Планируется ли регистрация в Google Play Console ($25) и Microsoft Store? Готов ли владелец организовать закрытый тест (12 человек на 14 дней) для Google Play?
   - По Apple App Store: учитывая риск реджекта за сходство с Windows Calculator и стоимость $99/год, готовы ли мы ограничиться версией для macOS через прямой `.zip` / Homebrew, отложив публикацию в iOS App Store?
4. **Приоритет инновационных режимов:**
   - Какое расширение функциональности наиболее приоритетно для следующего мажорного релиза: **MCP-сервер** для интеграции с AI-агентами (Claude/Cursor), **конвертер валют** или **режим свободного ввода (Free-form expression mode)**?
